# QA Curriculum Design

Comprehensive curriculum design methodology for QA Automation learning paths. Teaches how to structure testing education from fundamentals to advanced automation.

## When to Use This Skill

Use this skill when:
- Designing a new QA Automation learning path
- Creating lessons on testing fundamentals
- Structuring test automation curriculum
- Planning hands-on QA exercises

## Learning Path Structure

### Phase 1: Foundations (2-3 weeks)
**Topics:**
- What is QA and why it matters
- Types of testing (unit, integration, E2E, regression)
- Manual testing basics
- Test case design techniques
- Bug reporting and tracking

**Learning Outcomes:**
- Understand the role of QA in software development
- Write effective test cases
- Identify, document, and report bugs

### Phase 2: Test Automation Basics (3-4 weeks)
**Topics:**
- When to automate and when not to
- Programming fundamentals for automation engineers
- Setting up automation frameworks
- Writing first automated tests
- Locators and element selection

**Learning Outcomes:**
- Distinguish automation-appropriate scenarios
- Write simple automation scripts
- Understand framework architecture

### Phase 3: Advanced Automation (4-5 weeks)
**Topics:**
- Test design patterns (Page Object, Factory)
- Data-driven testing
- Parallel execution
- CI/CD integration
- Test reporting and metrics

**Learning Outcomes:**
- Design maintainable test suites
- Integrate tests into CI/CD pipelines
- Generate meaningful test reports

### Phase 4: Engineering Best Practices (3-4 weeks)
**Topics:**
- Code quality in test automation
- Handling flaky tests
- Performance testing integration
- Security testing basics
- Scalable test architecture

**Learning Outcomes:**
- Write production-quality automation code
- Troubleshoot and prevent flaky tests
- Scale automation across large applications

## Exercise Design Principles

### Hands-On Exercises
Every lesson includes practical exercises following these patterns:
1. **Warm-up** (15-20 min): Simple practice with the new concept
2. **Guided practice** (30-45 min): Step-by-step with hints
3. **Independent practice** (60-90 min): Apply concept independently
4. **Challenge** (optional): Extend beyond the core concept

### Exercise Structure
Each exercise should include:
- Clear objective
- Prerequisites
- Starter code (if applicable)
- Step-by-step instructions
- Expected outcome
- Solution hints
- Solution (hidden/spoiler)

## Assessment Guidelines

### Formative Assessments
- Check understanding after each lesson
- Quick quizzes (5-10 questions)
- Practical mini-tasks

### Summative Assessments
- At the end of each phase
- Practical project requiring multiple concepts
- Rubric-based grading

### Assessment Rubric Dimensions
1. **Conceptual Understanding** (25%): Explains why, not just how
2. **Code Quality** (30%): Readable, maintainable, follows best practices
3. **Completeness** (25%): All requirements met
4. **Problem Solving** (20%): Approaches and resolves issues independently
