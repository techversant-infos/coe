# Course Content Rules

Hard rules that govern all learning content quality and structure.

## Content Structure

- Every phase MUST have a README.md with clear objectives and overview
- Every phase MUST have lessons, exercises, and assessment
- Every lesson MUST have learning objectives
- Every exercise MUST have objective, prerequisites, instructions, expected outcome, and solution
- Every assessment MUST have rubric with measurable criteria
- All content MUST use templates from `.claude/templates/`

## Pedagogical Principles

- Progressive difficulty: Start simple, increase complexity gradually
- Every concept MUST have at least one hands-on exercise
- No concept should be introduced without practical application
- Assessments MUST align with stated learning objectives
- Content MUST be scannable (headings, bullet points, code blocks)

## Technical Accuracy

- All code examples MUST be syntactically correct and runnable
- Code examples MUST include comments explaining key points
- No placeholder code (e.g., "/* your code here */")
- Tested with latest stable versions of tools/frameworks
- Security best practices must be demonstrated

## Language Standards

- Use present tense for instructions
- Use imperative mood ("Write a function", not "You should write")
- No passive voice ("The button was clicked" vs "Click the button")
- Sentences should be concise and direct
- Avoid jargon without explanation
- No AI-sounding language: "delve into", "leverage", "synergies", "robust", "in today's fast-paced", "I am pleased to"

## Accessibility

- Use descriptive link text (not "click here")
- Provide code alternatives for visual concepts
- Use tables for tabular data
- Maintain sufficient contrast for readability
- Provide alternative explanations for abstract concepts

## Consistency

- Use consistent terminology across all lessons
- Follow the same template structure throughout
- Maintain consistent code formatting
- Use consistent naming conventions
- Keep voice and tone uniform

## Completeness

- No orphaned exercises (every exercise links to lessons)
- No orphaned assessments (every assessment links to phase)
- No broken internal links
- All prerequisites are accurate
- All file references are correct

## Length Guidelines

- Lesson: 500-1500 words (concept + examples)
- Exercise: 150-400 words (instructions + hints)
- Assessment: 200-500 words (description + rubric)
- Avoid walls of text; use headings and lists
- Keep concepts focused (one topic per lesson)

## Feedback Standards

- Provide examples of good and bad code where relevant
- Explain WHY something works, not just HOW
- Address common misconceptions explicitly
- Offer paths for remediation when appropriate
