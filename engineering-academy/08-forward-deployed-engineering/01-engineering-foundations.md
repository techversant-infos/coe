# 01. Engineering Foundations

**Status:** Draft · **Owner:** CoE Team · **Last updated:** 2026-11-06 · **Next review:** 2027-02-06

This stage is the academy's [Engineering Foundations roadmap](../00-engineering-foundations/README.md), the shared
baseline for every Techversant engineer. If you have already completed it, show the evidence in the project below
and move on. Back to the [roadmap](./README.md).

## Git and pull requests

The branching, commit, pull request and release model. On a client project, the pull request is also how the
client's team learns what you changed and why.

**What to learn:** branch naming, Conventional Commits, pull requests with verification notes, promotion and
rollback.

**Resources:** [01. Git and Pull Requests](../00-engineering-foundations/01-git-and-pull-requests.md)

**Level:** Foundation · Core

## Working with AI tools

Using AI coding assistants such as Claude Code, Cursor and Copilot safely: choosing a delegation level, checking the
output, keeping Red Zone work out of AI generation, and keeping client data out of tools not approved for it.

**What to learn:** the four delegation levels, the delegation test and the Red Zone.

**Resources:** [02. Working with AI Tools](../00-engineering-foundations/02-working-with-ai-tools.md)

**Level:** Foundation · Core

## Clean code and design

Code another developer can understand and change: clear names, small functions, design principles and decisions
recorded with their trade-offs.

**What to learn:** clean code, SOLID and dependency injection, change scenarios and architecture decision records.

**Resources:** [03. Clean Code](../00-engineering-foundations/03-clean-code.md),
[04. Design Principles](../00-engineering-foundations/04-design-principles.md) and
[05. Design Thinking](../00-engineering-foundations/05-design-thinking.md)

**Level:** Practitioner · Core

## Testing and code review

Proving a change works, improving code safely, and reviewing teammates' work with an objective checklist.

**What to learn:** test levels, clear tests, safe refactoring and the Techversant review checklist.

**Resources:** [07. Testing and Refactoring](../00-engineering-foundations/07-testing-and-refactoring.md) and
[09. Code Review](../00-engineering-foundations/09-code-review.md)

**Level:** Practitioner · Core

## Secure engineering

The security basics for anyone who touches APIs, secrets, permissions or personal data, and knowing when to ask for
a security review.

**What to learn:** secrets, injection, server-side authorization and the security review triggers.

**Resources:** [06. APIs and Boundaries](../00-engineering-foundations/06-apis-and-boundaries.md) and
[08. Secure Engineering](../00-engineering-foundations/08-secure-engineering.md)

**Level:** Foundation · Core

## Communication and ownership

Clear pull request descriptions, status updates and handoff notes. FDEs write for the client as well as for
colleagues.

**What to learn:** the pull request, blocker update and handoff note structures, and tracking technical debt.

**Resources:** [10. Communication and Ownership](../00-engineering-foundations/10-communication-and-ownership.md)

**Level:** Foundation · Core

## Project: Show Your Foundations Evidence

**Brief:** If you have completed Engineering Foundations, show your lead the signed-off
[capstone](../00-engineering-foundations/README.md#capstone). If not, complete its ten projects first, or show
equivalent evidence from your real work for each item below.

**Size:** 1–2 hours to collect, if you have completed Foundations

**Verification**, checked by your lead:

- [ ] A merged pull request of yours that follows the Techversant Git workflow
- [ ] You place five tasks your lead gives you at the right delegation level from
  [section 2.1 of the AI Era Coding Guidelines](../../standards/general/ai-era-coding-guidelines.md#21-delegation-levels),
  including at least one Red Zone task
- [ ] In a pull request your lead picks, you list the security risks and match them to the
  [Security Audit Checklist](../../security/audit/security-audit-checklist.md)
- [ ] A review you wrote on a colleague's pull request using the
  [Foundations review checklist](../00-engineering-foundations/09-code-review.md#the-review-checklist)
- [ ] A pull request description and a handoff note written with the
  [Foundations structures](../00-engineering-foundations/10-communication-and-ownership.md)
