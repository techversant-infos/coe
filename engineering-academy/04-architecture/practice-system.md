# Practice System: RealWorld and the Growth Brief

**Status:** Draft · **Owner:** CoE Team · **Last updated:** 2026-11-06 · **Next review:** 2027-02-06

The projects in the [Software Architect roadmap](./README.md) all design the same system: the open-source RealWorld
blogging app, run for a fictional client with a year of growth ahead. Using one system means each project builds on
the last, and reviewers can compare designs fairly.

## The App: RealWorld

RealWorld, also called Conduit, is a Medium-style blogging app. Users sign up, follow authors, write articles, add
tags, comment and favourite articles. The project publishes one API specification, and the community has built many
front ends and back ends against it, so you can pick one in your own stack.

Checked against the repository on 6 November 2026.

| Detail | Value |
|--------|-------|
| Repository | [realworld-apps/realworld](https://github.com/realworld-apps/realworld) |
| Licence | MIT, in the repository's `LICENSE` file |
| Specification | An OpenAPI file and API test suites in `specs/api`, and Playwright end-to-end tests in `specs/e2e` |
| Documentation | [docs.realworld.show](https://docs.realworld.show/) |
| Implementations | Listed on [codebase.show](https://codebase.show/projects/realworld), filtered by language and framework |

### Getting It Running

1. Pick one back end and one front end from [codebase.show](https://codebase.show/projects/realworld). Choose a
   back end in a stack Techversant uses, such as Node.js with TypeScript or PHP, and check its licence before you
   start.
2. Clone both, follow their README files, and point the front end at your back end.
3. Run the API test suite from `specs/api` against your back end, and record which tests pass. This is your
   baseline: after any change you make, the same tests must still pass.

Use it for practice only. Do not deploy it with real users' data, and do not copy its code into client work.

## The Growth Brief

**The client:** Lantern Media, a fictional publisher of local news and opinion in Kerala, runs its community blog on
the RealWorld app. Today it has about 5,000 monthly active users, almost all reading on the web.

**What Lantern wants in the next 12 months:**

1. **Ten times the users.** 50,000 monthly active users, with traffic peaks of about 20 times the average when a
   story goes viral.
2. **A mobile app** for Android and iOS that uses the same API as the website.
3. **Notifications** by email and mobile push when an author you follow publishes, or someone comments on your
   article.
4. **Article summaries** generated by AI, shown at the top of long articles, and suggestions for related articles.
5. **The old blog moved in.** Ten years of articles and comments still live in Lantern's old ColdFusion blog, which
   is the [BlogCFC5 practice app](../07-consulting/coldfusion/reference/practice-app-blogcfc5.md). They must move into
   the new system, with their old links still working.
6. **Staff sign-in** through Lantern's Microsoft Entra ID for editors and moderators. Readers keep signing in with
   email and password.

**Constraints:**

- **Service levels:** reading articles must be available 99.9% of the time in a month; writing and commenting 99.5%.
- **Budget:** running costs, including cloud services and AI provider charges, must stay under USD 1,500 a month at
  the new traffic.
- **Data:** readers are mostly in India, with some in the European Union. Their personal data falls under India's
  Digital Personal Data Protection Act, 2023, and the DPDP Rules, 2025, whose main duties apply from 13 May 2027, and
  under the EU's GDPR.
- **Team:** five developers and one tester, who will build and run whatever you design.
- **Recovery:** after a disaster, the site must be back within four hours, losing at most 15 minutes of data.

Everything else is yours to decide, record and defend. If the brief does not answer a question, write down the
assumption you made, as you would on a real project.
