# Junior Engineer to Senior Engineer

> **Who this is for:** Engineers who can complete assigned tasks and now need to own larger work with less supervision.
> **Transition goal:** Move from task execution to reliable feature ownership and technical judgment inside the team.

## What This Role Is Not

Senior Engineer is not simply the person who writes the most code. The difference is judgment: clearer design, safer delivery, better reviews, stronger ownership, and useful mentoring.

## Prerequisites

- Engineering Foundations complete or equivalent evidence.
- Practitioner level in the relevant discipline.
- At least 3 significant features, fixes, or quality improvements completed with review.
- Consistent PR hygiene: clear description, test notes, and responsive review handling.

## Capabilities To Build

### Technical

- Break a feature into small, reviewable changes.
- Apply clean code, SOLID, testing, and refactoring basics.
- Design simple APIs or components with clear boundaries.
- Write or improve tests around important behavior.
- Handle errors, edge cases, and rollback thinking.

### Collaboration

- Review junior PRs with specific, respectful feedback.
- Explain trade-offs without turning every choice into a debate.
- Raise blockers early with evidence and options.
- Write handoff notes that another engineer can act on.

### Ownership

- Own a feature from clarification to release notes.
- Identify risks before implementation starts.
- Leave the codebase easier to understand than you found it.
- Mentor one junior engineer through a small task or PR.

## Capstone Options

Choose one with your mentor:

1. Lead a medium-complexity feature end-to-end, including tests and rollout notes.
2. Refactor a legacy module with measurable readability/testability improvement.
3. Design and implement a testing strategy for one feature or service.

## Evidence Checklist

- [ ] I can explain the design of a feature I owned.
- [ ] I can show tests that protect important behavior.
- [ ] I can show at least 3 useful code reviews I gave to others.
- [ ] I can document trade-offs in a short ADR or PR note.
- [ ] I can identify and reduce technical debt without rewriting everything.
- [ ] I can mentor a junior engineer through a review cycle.
