# QA Engineer Capstone Assessment Rubric

This rubric evaluates a QA engineer's capabilities against the academy's progression model. It's used by managers and mentors to assess promotion readiness.

## Assessment Process

1. Engineer completes a capstone project from their path
2. Engineer submits evidence (documentation, code, reports)
3. Mentor and manager review using this rubric
4. Final decision includes promotion recommendation and growth areas

## Level Breakdowns

### Junior QA Engineer (Foundation)

**What this person needs:**
- Manual test creation and execution fundamentals
- Bug reporting best practices
- Test data management basics

**Capstone Options:**
1. Test a complete user journey with clear risk assessment
2. Create a test data strategy for one feature area
3. Document a test plan for a small feature release

| Criteria | Proficient | Developing | Needs Growth |
|---|---|---|---|
| **Test Coverage** | Covers happy path and key failure modes | Missing some edge cases | Only covers basic paths |
| **Bug Quality** | Clear steps, reproducible, links to context | Steps are vague but reproducible | Hard to reproduce, missing context |
| **Data Strategy** | Basic setup/teardown documented | Setup documented but missing teardown | No test data strategy |
| **Reporting** | Timely updates, clear status | Status updates late or unclear | Sporadic updates |

### Senior QA Engineer (Practitioner)

**What this person needs:**
- Automation framework basics and maintenance
- Test strategy and planning
- API and performance testing fundamentals

**Capstone Options:**
1. Build and maintain Playwright automation for one feature area
2. Create a test strategy for a major feature release
3. Implement API testing with BDD approach for one service

| Criteria | Proficient | Developing | Needs Growth |
|---|---|---|---|
| **Automation Quality** | Stable, maintainable, good coverage | Flaky, hard to maintain, low coverage | Unstable, not maintained |
| **Test Design** | Covers critical flows, data-driven tests | Focuses only on happy paths | No test design strategy |
| **API Testing** | Validates business rules and error cases | API coverage but limited validation | Only happy path tests |
| **Metrics** | Clear pass/fail metrics, reduction in defects | Basic metrics but not actionable | No metrics or tracking |

### Senior QA Engineer (Advanced)

**What this person needs:**
- Performance and reliability engineering
- Accessibility testing strategy
- CI/CD integration with quality gates

**Capstone Options:**
1. Implement performance testing strategy with baseline
2. Add accessibility testing to existing automation
3. Design quality gates for CI pipeline

| Criteria | Proficient | Developing | Needs Growth |
|---|---|---|---|
| **Performance** | Baselines, load testing, regression | Load tests but no baselines | No performance testing |
| **Accessibility** | WCAG compliance checks integrated | Basic accessibility tests | No accessibility testing |
| **CI Integration** | Quality gates, automated reports | Manual checks, no gates | No CI quality integration |
| **Reliability** | Flake analysis, stabilization efforts | Some flake awareness but no action | No focus on test reliability |

### QA Architect (Expert)

**What this person needs:**
- Test strategy and architecture
- Quality tooling evaluation
- Mentorship and quality culture

**Capstone Options:**
1. Design and implement test architecture for a new service
2. Research and implement a new testing tool/technology
3. Define and implement a quality dashboard with actionable insights

| Criteria | Proficient | Developing | Needs Growth |
|---|---|---|---|
| **Test Architecture** | Clear strategy aligned with business needs | Strategy exists but not aligned | No strategic thinking |
| **Tooling** | Evaluated, selected, documented solutions | Only uses existing tools | No tool evaluation skills |
| **Mentorship** | Trains others, shares knowledge | Participates but not active | No mentorship efforts |
| **Quality Culture** | Influences team standards, continuous improvement | Follows standards but doesn't improve | No awareness of quality culture |

## Promotion Assessment

### Ready for Promotion

Engineer demonstrates proficiency in:
- All criteria for current level
- Consistent evidence across projects
- Clear ownership and impact
- Mentor feedback confirms readiness

### Needs Development

If any "Needs Growth" criteria exist, plan includes:
- Specific improvement actions
- Mentor support areas
- Timeline for reassessment
- Support for growth opportunities

## Evidence Checklist

Engineer must provide:
- [ ] Capstone project artifacts (code, docs, reports)
- [ ] Evidence of previous work products
- [ ] Self-assessment against rubric
- [ ] Mentor feedback and evaluation
- [ ] Manager assessment and feedback
- [ ] Growth plan if not promotion-ready

## Timeline

1. Engineer submits capstone and evidence
2. Review within 2 weeks by mentor
3. Manager review within 3 weeks
4. Feedback and development plan within 4 weeks
5. Promotion decision within 5 weeks
