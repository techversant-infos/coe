# Consulting Operating Model

> Internal processes and standards for delivering ColdFusion consulting engagements.

---

## Purpose

This module defines how the consulting practice operates internally — from qualification through delivery and quality review. It ensures consistent, professional engagement delivery.

---

## 1. Engagement Lifecycle

### 1.1 Qualification Stage

**Entry Criteria:**
- Initial inquiry received
- Basic fit assessment completed
- Decision-maker identified

**Activities:**

| Activity | Owner | Output |
|----------|-------|--------|
| Initial discovery call | Sales/Consultant | Call notes |
| Fit assessment | Sales | Go/No-Go decision |
| Budget confirmation | Sales | Confirmed budget range |
| Timeline alignment | Sales | Target timeline |

**Exit Criteria:**
- Clear business problem identified
- Budget confirmed ($15K minimum)
- Timeline agreed (target)
- Decision-maker engaged

**Go/No-Go Checklist:**

- [ ] ColdFusion application confirmed
- [ ] Decision-maker met
- [ ] Business problem clear
- [ ] Budget in range
- [ ] Timeline reasonable
- [ ] No conflict of interest
- [ ] Team capacity available

### 1.2 Discovery Stage

**Entry Criteria:**
- SOW signed or verbal commitment
- Statement of work in development

**Activities:**

| Activity | Owner | Duration |
|----------|-------|----------|
| Discovery workshop | Consultant | 2-4 hours |
| Technical deep-dive | Consultant | 1-2 days |
| Documentation review | Consultant | 0.5-1 day |
| Assessment report | Consultant | 1-2 days |

**Deliverables:**
- Discovery workshop notes
- Technical environment summary
- Initial findings (verbal)
- Engagement scope definition

### 1.3 Proposal Stage

**Entry Criteria:**
- Discovery complete
- Scope defined
- Estimate approved

**Activities:**

| Activity | Owner | Duration |
|----------|-------|----------|
| Estimate development | Consultant | 0.5-1 day |
| Proposal writing | Consultant + Sales | 1-2 days |
| Internal review | Practice Lead | 1 day |
| Proposal delivery | Sales | 1 day |

**Proposal Components:**

1. Executive Summary (1 page)
2. Understanding (1 page)
3. Scope of Work (2-3 pages)
4. Approach (2-3 pages)
5. Timeline (1 page)
6. Investment (1 page)
7. Terms (1 page)
8. Appendices (as needed)

### 1.4 Delivery Stage

**Entry Criteria:**
- SOW signed
- Deposit received
- Access provisioned

**Activities:**

| Phase | Activities | Duration |
|-------|------------|----------|
| Initiation | Kickoff, access, plan | 1 week |
| Execution | Core work | Per SOW |
| Closure | Delivery, handoff | 1 week |

**Delivery Standards:**

- Weekly status updates (every Monday)
- Risk escalation within 24 hours
- Change control for any scope change
- Document all client decisions
- Maintain engagement log

### 1.5 Quality Review

**Before Client Delivery:**

| Check | Owner | Timing |
|-------|-------|--------|
| Technical accuracy | Peer consultant | 24 hours before |
| Language review | Practice Lead | 24 hours before |
| Format check | Consultant | 12 hours before |

**Quality Checklist:**

- [ ] All deliverables complete
- [ ] Executive summary is clear
- [ ] Recommendations are actionable
- [ ] Estimates are realistic
- [ ] No technical errors
- [ ] Formatting consistent
- [ ] No sensitive data exposed
- [ ] Client-friendly language

## 3. Documentation Standards

### 3.1 Report Format

All client-facing documents follow this format:

```
1. Executive Summary (1 page)
   - Key findings
   - Recommendations
   - Investment summary

2. Current State (3-5 pages)
   - Environment
   - Architecture
   - Assessment findings

3. Recommendations (3-5 pages)
   - Options analysis
   - Recommended approach
   - Risks and mitigations

4. Implementation (2-3 pages)
   - Scope
   - Timeline
   - Investment

5. Appendices
   - Technical details
   - Data tables
   - Methodology
```

### 3.2 Assumption Document

Every proposal includes an assumptions section:

**Standard Assumptions:**
- Client will provide timely access to systems and documentation
- Key stakeholders will be available for required meetings
- Environment will be available for testing
- Client will provide feedback within 5 business days
- Scope changes will follow change control process

**Project-Specific Assumptions:**

## 4. Internal Processes

### 4.1 Peer Review

**Before Delivery to Client:**

1. Consultant completes draft
2. Peer reviews for accuracy (24 hours)
3. Practice Lead reviews for quality (24 hours)
4. Consultant incorporates feedback
5. Final check by Practice Lead

**Review Criteria:**
- Technical accuracy
- Language and tone
- Formatting consistency
- Completeness
- Actionability

### 4.2 Escalation

**Level 1: Consultant**
- Day-to-day decisions
- Technical questions
- Client requests

**Level 2: Practice Lead**
- Scope questions
- Resource allocation
- Client escalations
- Technical blocks

**Level 3: Management**
- Contract issues
- Major scope changes
- Client relationship issues

### 4.3 Time Tracking

**Required for All Engagements:**

| Category | Description |
|----------|-------------|
| Discovery | Client meetings, workshop prep |
| Assessment | Code review, documentation |
| Reporting | Report writing, presentation |
| Delivery | Implementation work |
| Admin | Emails, coordination |
| Travel | Client site visits |

## 5. Quality Metrics

### 5.1 Engagement Health

Track per engagement:

| Metric | Target |
|--------|--------|
| On-time delivery | > 90% |
| On-budget delivery | > 85% |
| Client satisfaction | > 8/10 |
| Issue escalation rate | < 5% |
| Change order rate | < 10% |

### 5.2 Client Feedback

Request feedback at engagement close:

1. Overall satisfaction
2. Quality of deliverables
3. Communication effectiveness
4. Technical expertise
5. Recommendation likelihood
